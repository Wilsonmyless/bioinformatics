START HERE · BEFORE MODULE 1

Meet R: a tool for making sense of biological data

No coding or bioinformatics experience is needed. This short introduction explains what R is and where it fits in a research workflow.

What is R?

R is a programming language and software environment for working with data, statistics, and graphics. You give it instructions as code; it evaluates them and returns results you can inspect and build on.

Why do researchers use it?

R is open source and has packages that extend what it can do. A script records the steps of an analysis, while statistical and plotting tools help researchers explore data and communicate results.

What can we do with it?

In a dry lab, R can help organize sample metadata, inspect gene-expression counts, check data quality, summarize measurements, make plots, and apply suitable methods to genomic datasets.

Think like a researcher  R can carry out calculations and methods, but it cannot decide whether a study design is sound or a biological conclusion is justified. That still depends on the experiment, the data, and careful scientific judgment.

Your route through learneR

We’ll start with expressions and vectors, then practice debugging, sample identity, and quality checks. Later, you’ll inspect a small count matrix—the kind of table used in RNA-seq workflows—before building toward larger analyses.

LESSON 2 OF 6 · R FOUNDATIONS
Give your measurements a name
R objects hold data so you can reuse it. Vectors let you keep related measurements together in their original order.

    
Store related values in a vector
R evaluates the code on the right first. c() is a function: a named, reusable operation. It takes the values you give it and returns them together as a vector. The assignment arrow <- binds that result to the name counts.

    
What does c() do?
It combines the values inside its parentheses, in order. Here, four numbers become one numeric vector.
Why assign the result?
The name lets you refer to this vector again: inspect it, summarize it, or pass it into another function without retyping the values.

    
counts <- c(12, 18, 9, 15)
counts
length(counts)  # number of values → 4
R prints the vector when you type its name. The function length() answers a new question about that same object. Keeping values named makes later code easier to read and reuse.

    
A dry-lab use: inspect one gene across samples
Suppose a bulk RNA-seq count table has a row for one gene and columns for samples. You might pull out that row to inspect the gene’s raw read counts before analysis. Named entries make the sample association visible.
gene_counts <- c(control_1 = 142, control_2 = 151,
                 treated_1 = 130, treated_2 = 188)
gene_counts
Here, the values are hypothetical raw counts. Assigning them to gene_counts gives later steps a clear input, while the names help prevent mixing up which number belongs to which sample.
Interpret with care  Raw counts depend on sequencing depth and biological variability. This vector is useful for checking data and learning syntax; by itself, it cannot show that treatment changed expression. Differential expression uses the full count data with sample information and an appropriate design, typically including biological replicates.

LESSON 3 OF 6 · DEBUGGING PRACTICE
Repair a broken vector assignment
In a real analysis, one missing parenthesis can stop a script before any results are made. Learn to use R’s message as evidence, then fix the code.

    
Why debugging matters in a real analysis
A missing parenthesis is a small syntax error, but the same kind of mistake can stop a research script before it imports a count matrix, joins cell metadata, or calculates quality-control measures. Fixing errors carefully helps make sure each downstream step receives the data it was meant to use. Syntax errors stop code from being parsed; logic errors can run and still produce the wrong result, so inspect outputs as well as messages.
In a dry lab, reproducible debugging means making a small change, rerunning the relevant code, and checking the object and dimensions afterward. Silencing an error or changing filtering rules just to make a pipeline run can change which cells or genes enter later analyses.
Debugging habit  Read the error, inspect nearby code, change one thing at a time, rerun it, then check whether the object has the intended shape and values.
For examples of scRNA-seq quality-control and processing decisions, see Luecken & Theis, Molecular Systems Biology (2019).

LESSON 4 OF 6 · BIOLOGICAL DATA BASICS
Keep track of biological replicates
Single-cell datasets may contain thousands of cells, but study design still depends on the people or samples those cells came from.

    
Cells are nested within donors
In multiplexed single-cell studies, cell-level measurements can be linked back to their donor. That identifier matters: cells from the same donor share biological background and are not independent biological replicates for a condition comparison. Count donors and preserve donor labels in metadata before choosing a statistical analysis.

LESSON 7 · TABLES & METADATA
Build and inspect a sample metadata table
Data frames are the everyday table structure in R. Rows represent samples or cells; columns store measured or recorded properties.


Keep identifiers and measurements together
A count matrix holds measurements. A separate metadata table explains each sample: sample ID, donor, treatment, batch, tissue, or time point. The sample ID links the two, so verify alignment before analyzing.
samples <- data.frame(
  sample_id = c("S01", "S02", "S03", "S04"),
  donor = c("D1", "D1", "D2", "D2"),
  condition = c("control", "treated", "control", "treated")
)
str(samples)
head(samples)
names(samples)
data.frame() creates columns of equal length. str() reveals structure and types; head() previews rows; names() checks column names. These quick inspections should happen before calculations.
Understand each column's type
IDs and labels are usually character or factor values. Counts should be numeric integers. A treatment group is categorical, not a number to average. Use str(), table(), and uniqueness checks to see what R actually read.
table(samples$condition)
length(unique(samples$donor))
stopifnot(!anyDuplicated(samples$sample_id))
Bioinformatics check  Compare metadata sample IDs with count-matrix column names. Missing, duplicated, or misordered IDs can attach a condition to the wrong measurements.

LESSON 8 · TYPES, LOGIC & MISSING VALUES
Subset data without losing its meaning
Indexing and logical conditions select observations. Type conversion and missing values can create quiet errors.


Rows, columns, and logical filters
For a data frame, samples[rows, columns] selects rows before the comma and columns after. A logical condition gives one TRUE/FALSE result per row. Combine conditions with & for AND and | for OR; use parentheses to make intent clear.
treated <- samples[samples$condition == "treated", ]
subset_ids <- samples[
  samples$donor == "D1" & samples$condition == "treated",
  "sample_id"
]
Use == to test equality; <- assigns a result. A common error is writing = when a comparison was intended. When subsetting matrices, use drop = FALSE if you need to preserve matrix shape when one row or column remains.
Missing is not zero
R represents missing values as NA. It is not equal to zero, and comparisons involving it can also return NA. Check missingness explicitly with is.na(). Choose what to do based on the data's meaning; never replace missing measurements with zero only to silence an error.
sum(is.na(samples$condition))
complete.cases(samples)
samples[!is.na(samples$condition), ]
Research habit  After filtering, report how many rows remain and which samples were removed. A filter that changes donor or condition representation can change the scientific question.
Checkpoint: Explain why a missing count, a true zero count, and an absent sample are different.

LESSON 10 · FUNCTIONS & CONTROL FLOW
Turn repeated work into reusable code
Functions make steps explicit. Conditions and loops apply steps across inputs; checks catch unexpected data.


A function has inputs and an output
Define a function with function(). Arguments are inputs; the final expression is returned. Choose a specific name and state assumptions. Avoid hidden dependencies on objects in the global workspace.
count_cells <- function(cell_ids) {
  if (length(cell_ids) == 0) {
    stop("Provide at least one cell ID")
  }
  length(unique(cell_ids))
}
count_cells(c("C1", "C2", "C1"))
This returns distinct IDs, not records. Test ordinary input, empty input, and unexpected types. Use if for a single TRUE/FALSE decision; use for to repeat over a sequence. Vectorized operations and established workflows are often clearer for assay computations.
for (sample_name in names(sample_files)) {
  message("Preparing: ", sample_name)
}
Don't hide failures  Fail clearly when assumptions are broken. Broad error suppression can turn a bad input into a plausible-looking output.

LESSON 11 · TIDY TABLES & SUMMARIES
Prepare data for the biological question
Long-form tables support grouping, summarizing, joining, and plotting. Inspect the data shape before transforming it.


One observation per row
A tidy table usually has one variable per column and one observation per row. A cell-QC table might have cell ID, donor, detected genes, library size, and mitochondrial fraction. This shape makes operations explicit.
qc_summary <- cell_qc |>
  dplyr::group_by(condition) |>
  dplyr::summarise(
    median_genes = median(n_genes, na.rm = TRUE),
    cells = dplyr::n(),
    .groups = "drop"
  )
The base R pipe |> passes the value on its left to the next call. group_by() defines groups; summarise() reduces them to rows. Summaries do not replace inspecting distributions or donor-level replication.
Join only on verified keys
Joins combine tables by identifiers. Check key uniqueness and unmatched rows before and after; many-to-many joins can multiply rows without an obvious error.
sum(duplicated(metadata$sample_id))
setdiff(count_sample_ids, metadata$sample_id)
setdiff(metadata$sample_id, count_sample_ids)
Checkpoint  Before summarizing by treatment, identify the independent units. In many studies, biological samples or donors—not individual cells—provide replication.
Reference: summarise() · dplyr joins.




LESSON 12 · VISUALIZATION
Use plots to inspect, not decorate
Plots reveal distributions, outliers, sample structure, and possible batch effects. Match the graphic to the data and question.


Map variables to visual properties
In ggplot2, provide a data frame, map variables with aes(), then add a geometry. Mappings encode data; fixed settings such as a constant point colour do not.
ggplot2::ggplot(cell_qc, ggplot2::aes(x = condition, y = n_genes)) +
  ggplot2::geom_boxplot(outlier.shape = NA) +
  ggplot2::geom_jitter(width = 0.12, alpha = 0.25) +
  ggplot2::labs(x = "Condition", y = "Genes detected per cell")
A boxplot summarizes a distribution; jittered points reveal observations. Because many cells can come from one donor, a dense cloud of cells is not many independent replicates. Add donor summaries or facets when they clarify structure.
Inspect before interpreting
Check axes, units, sample sizes, missingness, outliers, and transformations. Avoid truncated axes that exaggerate differences. Save figures with informative names and keep the code that generated them.

LESSON 13 · DESIGN & STATISTICAL INFERENCE
Make the design match the question
Good code cannot rescue a confounded or under-replicated study. Identify the independent unit before choosing a model.


Replication and confounding
Biological replicates are independently sampled units appropriate to the question. Technical repeats and multiple cells from one donor do not automatically create biological replication. Record relevant covariates such as batch, donor, and processing conditions. If condition and batch are perfectly confounded, their effects cannot be disentangled from these data.
Write the design in words first: outcome, comparison, replicate unit, and covariates. Check that the available samples support the intended comparison. Thousands of cells are not thousands of independent donors.
Effect sizes, uncertainty, and many genes
A p-value is not the probability that a hypothesis is true or a measure of effect size. Report estimates and uncertainty. Testing many genes creates a multiple-testing problem; use and report false-discovery-rate adjustment. Exploratory plots do not replace a model aligned with design.
Before analyzing  Can condition be distinguished from batch? What is the biological replicate? Are samples paired? Which contrast answers the question? Pause if these are unclear.
Bioconductor's RNA-seq training materials cover design, replication, covariates, and count data.




LESSON 14 · BULK RNA-SEQ
From raw counts to a defensible comparison
Understand the steps in gene-level RNA-seq analysis. The code is a conceptual template; it needs a suitable, verified dataset.


Know what the input means
A count matrix has genes in rows and samples in columns. DESeq2 expects raw integer counts from a suitable counting workflow—not TPM, FPKM, rounded normalized values, or arbitrary log values. Metadata rows must align with matrix columns.
Fit a model for the design
library(DESeq2)
stopifnot(identical(colnames(counts), rownames(coldata)))
dds <- DESeqDataSetFromMatrix(
  countData = counts, colData = coldata,
  design = ~ batch + condition
)
dds <- DESeq(dds)
res <- results(dds, contrast = c("condition", "treated", "control"))
The design formula describes how counts depend on recorded variables and must be supported by the study. DESeq2 estimates size factors and dispersion. Normalized counts can support some visualizations, but the test is based on raw counts and the model.
Inspect and report
Check sample distances, exploratory ordination, library sizes, dispersion estimates, fold changes and uncertainty, adjusted p-values, and filtering. Preserve gene IDs and record genome and annotation releases. A significant result is evidence under a model, not proof of mechanism or clinical relevance.
Interpretation boundary  Explain the design, effect size, uncertainty, multiple-testing procedure, and limitations. Seek biological context and follow-up evidence.
Read the DESeq2 vignette and Bioconductor's RNA-seq workflow training.




LESSON 15 · SINGLE-CELL DATA & QC
Understand the single-cell experiment object
Single-cell RNA-seq adds cell-level observations and sparse data structures, while sample identity and replication remain essential.


Assays plus annotations
Expression data use feature and cell dimensions, but conventions differ across tools: verify which axis contains genes. A SingleCellExperiment stores assay matrices with per-cell metadata (colData) and per-feature metadata (rowData).
library(SingleCellExperiment)
assayNames(sce)
dim(sce)
head(colData(sce))
head(rowData(sce))
Single-cell matrices are often sparse because most genes are zero in most cells. Sparse storage saves memory. Avoid converting a large sparse matrix to dense form without checking its size.
QC is evidence, not a universal cutoff
Inspect library size, genes detected, and mitochondrial proportion by sample and donor. Thresholds depend on tissue, protocol, chemistry, sequencing depth, and goals; a cutoff from another paper is not automatically appropriate. Record removed cells and reasons.
Replicate reminder  Retain donor, sample, and batch labels throughout. Cells are nested within samples; condition comparisons must account for the experimental unit.
Official references: SingleCellExperiment introduction · scater.




LESSON 16 · NORMALIZATION & DIMENSION REDUCTION
Explore cell structure without overclaiming
Normalization and dimension reduction help explore complex data. They do not remove technical variation or replace study design.


Keep track of representations
Keep raw counts available. Normalized or log-transformed assays support visualization and particular downstream methods, but are not interchangeable with raw counts in every model. Follow the selected package workflow and record which assay and transform you use.
Embeddings and clusters are hypotheses
PCA is a linear projection; UMAP is a nonlinear embedding for visualization. A two-dimensional layout is not a literal map of cell identity. Clustering depends on feature selection, dimensions, graph construction, and resolution. Treat clusters as hypotheses to inspect, not automatically known cell types.
Color embeddings by sample, donor, condition, batch, and QC measures. A cluster associated almost entirely with one batch calls for technical investigation. Compare conclusions across sensible parameter choices.
Document choices  Report preprocessing, selected features, dimensions, neighbor settings, clustering resolution, software versions, and parameters.
See scater's documentation for single-cell QC, normalization, and visualization tools.




LESSON 17 · MARKERS & BIOLOGICAL INTERPRETATION
Use marker genes as evidence, not labels
Cluster annotation combines expression patterns, reference knowledge, sample context, and uncertainty. One gene rarely settles an identity.


Check more than one source of evidence
Ask whether candidate markers are detected in many cells in a cluster and are specific relative to other clusters. Consider ambient RNA, doublets, low-quality cells, and activation state as alternatives. Reference mapping can help, but results depend on reference tissue, species, platform, and preprocessing. Keep broad or unknown labels when evidence is weak.
Account for the experimental unit
Cells from one donor share biological and technical context. Treating every cell as an independent replicate can inflate certainty. For condition-level expression comparisons, sample-aware methods such as pseudobulk aggregation by biological sample and cell type can be appropriate. Check sample counts, cell numbers, covariates, and whether the design can estimate the comparison.
# Conceptual workflow:
# aggregate raw counts by biological sample and cell type
# then fit a design that reflects the study
# use a validated method and inspect its assumptions
Interpret cautiously  Report the annotation method, marker rationale, uncertainty, and sample representation. Avoid causal claims from cross-sectional association.

Import success does not mean data are correct. Check dimensions, IDs, types, missing values, and units. If dates, IDs, or gene identifiers were changed during import, correct the import settings or preserve them as text as appropriate.
Packages are documented tools
Packages extend R. Install a package once, load it in each session, and inspect help pages and vignettes. Use maintained tools suited to the assay; record package versions and session details. Bioconductor provides many packages and coordinated workflows for biological data.
library(Biobase)
packageVersion("Biobase")
sessionInfo()
Data safety  Check institutional rules before storing human or sensitive data in cloud services, public repositories, or third-party tools.
R introduction · Bioconductor installation.


LESSON 10 · FUNCTIONS & CONTROL FLOW
Turn repeated work into reusable code
Build a small function from the vector and metadata skills you already have.
Inputs, steps, and returned values
Define a function with function(). Arguments are inputs; the final expression becomes the output. Choose clear argument names and state assumptions. Functions make it easier to reuse one verified operation instead of copying slightly different code across samples.
count_distinct_ids <- function(ids) {
  if (length(ids) == 0) {
    stop("Provide at least one ID")
  }
  length(unique(ids))
}
count_distinct_ids(samples$donor)
The result is the number of distinct donors represented in the metadata. if checks a single TRUE/FALSE condition. for repeats an operation across values, such as file names. Vectorized functions or established assay workflows are often clearer for numerical work.
for (sample_name in names(sample_files)) {
  message("Preparing: ", sample_name)
}
Test a function with ordinary input and edge cases such as empty input. Prefer a clear error to a silent fallback. Avoid hidden reliance on variables in the global workspace.
Checkpoint  What should the function do if an ID is missing? Make that decision explicit rather than assuming.


LESSON 11 · TIDY TABLES & SUMMARIES
Transform data to answer a question
Reuse your metadata table, and learn how grouping and joins can either clarify or corrupt an analysis.
Shape observations clearly
A tidy table typically has one variable per column and one observation per row. A cell-level QC table might have a row per cell and columns for cell ID, donor, detected genes, library size, and mitochondrial fraction.
qc_summary <- cell_qc |>
  dplyr::group_by(condition) |>
  dplyr::summarise(
    median_genes = median(n_genes, na.rm = TRUE),
    cells = dplyr::n(),
    .groups = "drop"
  )
The base R pipe |> passes the value on its left to the next operation. group_by() defines groups; summarise() reduces each group to a row. State the unit being summarized: cells, samples, or donors are not interchangeable.
Join with verified keys
Before joining measurement tables to samples, check whether the key is unique and whether IDs are missing on either side. A many-to-many join can multiply rows without an error.
sum(duplicated(samples$sample_id))
setdiff(count_sample_ids, samples$sample_id)
setdiff(samples$sample_id, count_sample_ids)
Checkpoint  What is one way to detect an accidental many-to-many join before interpreting a summary?

LESSON 12 · VISUALIZATION
Use plots to inspect, not decorate
Use your growing QC table to look for distributions, outliers, sample structure, and batch effects.
Map variables to visual properties
In ggplot2, provide data, map variables with aes(), then add a geometry. A mapping encodes data; fixed settings such as a constant colour do not.
ggplot2::ggplot(cell_qc, ggplot2::aes(x = condition, y = n_genes)) +
  ggplot2::geom_boxplot(outlier.shape = NA) +
  ggplot2::geom_jitter(width = 0.12, alpha = 0.25) +
  ggplot2::labs(x = "Condition", y = "Genes detected per cell")
A boxplot summarizes a distribution; jittered points show observations. Thousands of cells from a few donors are not thousands of independent replicates. Add donor-level views when they clarify the experiment.
Inspect before interpreting
Check axes, units, sample sizes, missingness, outliers, and transformations. Avoid axes or colors that exaggerate differences. Save figures with useful names and retain the code that created them.
Checkpoint  What can a QC plot diagnose? What can it not establish about a treatment effect?
ggplot() · aes().


LESSON 13 · DESIGN & STATISTICAL INFERENCE
Make the design match the question
Before fitting a model, decide what is being compared and which observations count as independent replication.
Replication and confounding
Biological replicates are independently sampled units appropriate to the question. Technical repeats and multiple cells from the same donor do not automatically create biological replication. Record relevant covariates such as batch, donor, and processing conditions. If condition and batch are perfectly confounded, their effects cannot be separated from those data alone.
State the outcome, contrast, replicate unit, and covariates in words first. Check that the available design supports the comparison. A p-value is not the probability that a hypothesis is true or a measure of effect size.
Many genes means many tests
Genome-wide analyses test many features. Report effect estimates and uncertainty alongside p-values and use an appropriate false-discovery-rate procedure. Exploratory plots are useful but do not replace a model aligned with the design. Document exclusions and avoid changing filters merely to obtain significance.
Pause and ask  Can condition be distinguished from batch? Are samples paired? Which unit is replicated? Which contrast answers the biological question?
Bioconductor RNA-seq course materials discuss design, replication, covariates, and count data.


LESSON 14 · BULK RNA-SEQ
From raw counts to a defensible comparison
Connect the count-matrix work to a documented differential-expression workflow. The code is a template requiring verified study data.
Understand the input and design
A gene count matrix has genes in rows and samples in columns. DESeq2 expects raw integer counts from an appropriate counting workflow—not TPM, FPKM, rounded normalized values, or arbitrary log values. Metadata must align exactly with matrix columns.
library(DESeq2)
stopifnot(identical(colnames(counts), rownames(coldata)))
dds <- DESeqDataSetFromMatrix(
  countData = counts, colData = coldata,
  design = ~ batch + condition
)
dds <- DESeq(dds)
res <- results(dds, contrast = c("condition", "treated", "control"))
The formula encodes supported design factors. The workflow estimates size factors and dispersion. Normalized counts are useful for some displays, but the differential test uses the raw counts and model.
Inspect diagnostics and interpret
Check sample distances, exploratory ordination, library sizes, dispersion, fold changes, uncertainty, adjusted p-values, and filtering. Preserve gene IDs and record genome and annotation versions. A statistically significant result is not proof of mechanism or clinical importance.
Report responsibly  Describe the design, effect size, uncertainty, multiple-testing adjustment, and limitations. Interpret in biological context and seek appropriate validation.
DESeq2 vignette · Bioconductor RNA-seq workflow.


LESSON 15 · SINGLE-CELL DATA & QC
Understand the single-cell experiment object
Single-cell RNA-seq adds cell-level observations and sparse storage; sample identity and replication remain essential.
Assays and annotations
Expression data use feature and cell dimensions, but axis conventions differ across tools—verify them. A SingleCellExperiment keeps assay matrices with per-cell metadata (colData) and per-feature metadata (rowData).
library(SingleCellExperiment)
assayNames(sce)
dim(sce)
head(colData(sce))
head(rowData(sce))
Single-cell matrices are often sparse because most genes are zero in most cells. Sparse storage saves memory; converting a large sparse matrix to dense form can exhaust it.
Quality control is dataset-specific
Inspect library size, detected genes, and mitochondrial proportion by sample and donor. Thresholds depend on tissue, protocol, chemistry, sequencing depth, and goals. Record criteria and removed cells. Do not copy a cutoff from another study without checking its rationale and consequences.
Keep the thread  Preserve donor, sample, and batch labels through every step. Cells are nested within samples; condition comparisons must reflect the experimental unit.
SingleCellExperiment introduction · scater.


LESSON 16 · NORMALIZATION & DIMENSION REDUCTION
Explore cell structure without overclaiming
Keep raw counts and derived representations distinct as you explore cell-to-cell variation.
Track transformations
Normalized or log-transformed assays support visualization and specific methods, but are not interchangeable with raw counts in every model. Follow the package workflow and record which assay and transform you used.
Embeddings and clusters are hypotheses
PCA is a linear projection; UMAP is a nonlinear visualization. A 2D layout is not a literal map of cell identity. Clustering depends on selected features, dimensions, graph construction, and resolution. Color embeddings by donor, condition, batch, and QC metrics; batch-associated structure deserves investigation.
Document choices  Record preprocessing, feature selection, dimensions, neighbor settings, clustering resolution, software versions, and parameters. Check whether conclusions are stable to reasonable alternatives.
See scater for single-cell QC, normalization, and visualization.


LESSON 17 · MARKERS & BIOLOGICAL INTERPRETATION
Use marker genes as evidence, not labels
Cluster annotation combines expression patterns, reference knowledge, sample context, and uncertainty.
Evaluate more than one marker
Ask whether candidate genes are detected in many cells in a cluster and specific relative to other clusters. Consider ambient RNA, doublets, low-quality cells, and activation state as alternative explanations. Reference mapping can prioritize hypotheses, but results depend on tissue, species, platform, and preprocessing. Keep broad or unknown labels when evidence is weak.
Account for the experimental unit
Cells from one donor share biological context. Treating every cell as an independent replicate can inflate certainty. For condition-level comparisons, sample-aware approaches such as pseudobulk aggregation by biological sample and cell type can be appropriate. Check sample numbers, cell counts, covariates, and estimability; pseudobulk does not fix a flawed design.
Interpret cautiously  Report annotation method, marker rationale, uncertainty, and sample representation. Avoid causal claims from cross-sectional associations.


LESSON 18 · REPRODUCIBLE CAPSTONE
Make an analysis another researcher can review
Competence means more than producing a plot: explain the question, record decisions, check assumptions, and make the work rerunnable.
Project checklist
1. State the question: outcome, contrast, replicate unit, covariates. 2. Identify the data: source, access date, assay, reference genome, annotation release, use restrictions. 3. Inspect first: dimensions, identifiers, types, missingness, alignment. 4. Follow a documented workflow: distinguish raw counts, normalized values, and visualization transforms. 5. Validate decisions: record QC, exclusions, diagnostics, and sensitivity checks. 6. Report honestly: effects, uncertainty, multiple-testing adjustment, limitations, and software versions.
Organize the project
project/
  data_raw/       # original inputs; never overwrite
  data_processed/ # derived data and documented steps
  R/              # scripts and functions
  results/        # tables and figures
  README.md       # question, inputs, run order, decisions
Use relative paths and scripted run order. Save random seeds when stochastic steps are used. Ask another researcher to review the code and scientific assumptions.
Final field note  Reproducibility makes choices easier to inspect; it does not guarantee a valid design or conclusion.
Capstone: Analyze an appropriately documented teaching dataset. Report the question, metadata checks, QC, analysis rationale, results with uncertainty, and limitations. Do not claim beyond what the design supports.
Bioconductor training materials provide further guided practice.
